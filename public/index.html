The Problem

The Moment an Agent Can Spend,
Who Holds the Key?

Agents can reason and recommend. Spending is where the trust question starts.

Today: the Operator

The agent's code runs on their server, the wallet key sits in their config, and the only record of what happened is their logs. If they're breached or dishonest, your agent's money is theirs, and you can't prove what it did.

With OutLayer: Nobody

The NEAR MPC network issues the key into an Intel TDX enclave. The agent asks for signatures and spends under a policy stored on-chain. The operator holds nothing to steal.

The Solution

How the Keys Work

Nobody at OutLayer
Holds a Wallet Key

The NEAR MPC network issues the root secret through confidential key derivation (CKD). It exists only inside an approved enclave.

01

The Enclave Proves Its Code

The keystore boots inside an Intel TDX enclave and produces an attestation quote: Intel's signed proof of exactly which code is running.

02

The Chain Checks It

A NEAR contract checks Intel's signature chain, refuses out-of-date hardware, and compares the build's five measurements with the approved list. Only then may this enclave request a key.

03

A Public Request

The enclave asks the NEAR MPC network for its secret through CKD. The request is a public NEAR transaction, so every issuance is visible on-chain.

04

Encrypted to the Enclave

The MPC nodes compute the answer from their threshold shares and encrypt it to a one-time key generated inside the enclave. Whoever relays it, OutLayer included, sees only ciphertext.

05

Memory Only

The enclave decrypts the root secret and checks it against the MPC network's public key. It never touches disk. After a restart the enclave attests again and receives the same secret.

06

Every Wallet Key Derived Inside

NEAR, EVM and Solana keys are derived from that root inside the enclave. The agent's code gets signatures, never keys.

The result: there is no key for OutLayer to hand over, seize, or lose. A build that behaves differently needs a new on-chain approval that anyone can see. Want a root of your own? A vault issues one to your own NEAR contract, every derivation shows in your account's history, and you can take over your keys and leave at any time.

Agent Custody

Your Rules.
Keys That Can't Be Lost.

You set the policy. The agent spends within your rules. Private keys live inside the TEE and are re-derived on every operation — the agent never holds them and can never lose them.

One Wallet, Every Chain

Keys are derived inside the enclave from a root secret issued by the NEAR MPC network. The same wallet ID always produces the same addresses on NEAR, every EVM chain, and Solana. Stateless and deterministic — the TEE re-derives keys on every operation.

The agent never touches private keys. It asks the enclave for a signature, and the enclave signs after evaluating policy.

agent_wallet.rs 
// Get derived address on any chain
let near_addr = wallet::get_address("near")?;
let eth_addr  = wallet::get_address("ethereum")?;

// Transfer tokens
wallet::transfer("near", "bob.near", amount)?;

// Cross-chain swap via NEAR Intents
wallet::swap(
    "nep141:wrap.near",
    "nep141:usdc.near",
    amount, ""
)?;

// Withdraw to Ethereum
wallet::withdraw(
    "ethereum", "0xBob...",
    "1000000", "erc20:USDC"
)?;

Spending Limits

Per-transaction, hourly, daily, and monthly caps across all tokens. Per-transaction caps are enforced inside the enclave.

Address Whitelist

Restrict which addresses the agent can send to. Whitelist or blacklist mode — enforced in hardware, not in application code.

Multisig Approvals

Transactions above a threshold require 2-of-3 human approval via NEAR wallet signatures. TEE holds the transaction until the threshold is met.

Emergency Freeze

Owner calls freeze_wallet() directly on-chain. Takes effect in seconds. No API, no coordinator — works even if infrastructure is compromised.

terminal 
# Install
curl -fsSL https://raw.githubusercontent.com/out-layer/outlayer-cli/main/install.sh \
  | sh

# Log in with your NEAR account
outlayer login

# Create your first agent (edit src/main.rs)
outlayer create my-agent && cd my-agent

# Build, upload the .wasm, deploy it
./build.sh
outlayer upload out/my-agent.wasm
outlayer deploy my-agent <URL printed by upload>

# Create a payment key, then run
outlayer keys create
outlayer run alice.near/my-agent '{"command": "hello"}'
