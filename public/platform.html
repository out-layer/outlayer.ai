Secrets & Permissions

End-to-End Encrypted.
Access Checked Before Decryption.

Secrets Are a Cryptographic Primitive

Developers encrypt secrets in their browser using the keystore's public key. The encrypted blob lives on the NEAR blockchain. When the agent runs, the TEE fetches it, decrypts with a hardware-derived key, and injects as environment variables.

At no point does the operator, the coordinator, or any component outside the TEE see plaintext. Combined with Access Conditions, secrets are protected by both cryptography and hardware isolation, with access gated by on-chain conditions the TEE validates before decrypting.

Trust Model

Two Layers of
Unbreakable Security

To compromise OutLayer, an attacker must break both

Layer 1

Intel TDX

Hardware-enforced Trusted Execution Environment. Code runs inside CPU-encrypted memory. The server operator, the OS, and even physical access cannot extract secrets or tamper with execution.

  • CPU-level memory encryption
  • Remote attestation reports
  • Tamper-evident execution
  • Secrets never touch host OS
  • Post-quantum on-chain signatures (ML-DSA-65)
+
Layer 2

NEAR MPC Network

Independent node operators running threshold BLS cryptography. Key derivation is distributed — no single node ever sees the complete secret. The same network securing NEAR Intents and billions in cross-chain transactions.

  • Threshold of independent MPC nodes
  • BLS12-381 pairing-based cryptography
  • Deterministic yet distributed secrets
  • All operations auditable on-chain

The result: to steal a user's secret, an attacker must simultaneously break Intel TDX hardware isolation and compromise a threshold of independent MPC nodes operated by separate organizations. This is the same security model protecting billions in assets through NEAR Intents today.

Trust Model

Verify, Don't Trust

"Verifiable" is not a marketing adjective. It is a technical property backed by Intel TDX measurements approved on-chain and an attestation for every completed run.

Operator CANNOT

Hardware-enforced by Intel TDX

  • ✕ Read decrypted secrets or wallet private keys
  • ✕ Modify execution results
  • ✕ Run different code than what was deployed
  • ✕ Forge attestation reports
  • ✕ Extract storage encryption keys

Anyone CAN Verify

Publicly auditable

  • ✓ Exact code running in the enclave (TDX measurements)
  • ✓ Binary matches public source (Sigstore certificates)
  • ✓ Each completed run was attested (TDX quote over code, input and output)
  • ✓ 5 hardware measurements match approved set
  • ✓ Worker keys registered with verified TDX quotes

Intel TDX provides five hardware measurements (MRTD, RTMR0–3) that uniquely identify the code running inside the enclave. All five must match an approved set stored on the NEAR blockchain. Workers generate keypairs inside the TEE and register them on-chain with verified TDX attestation quotes; on-chain results are submitted with keys that never leave the enclave. Every completed run also carries a TDX quote over the code hash, the input and the output.

Architecture

How It Works

From request to verifiable result in seconds

01

Request Execution

Your smart contract or HTTPS app calls a published build: an OutLayer project or an immutable WASM URL with its hash. Attach payment in stablecoins.

02

Secrets Injection

The TEE Keystore validates access conditions, then derives decryption keys via CKD (NEAR MPC Network). User secrets are decrypted and injected as env vars — plaintext never leaves the enclave.

03

TEE Execution

Workers run your published WASM build inside Intel TDX hardware. Process fully isolated — no filesystem, no network access, instruction-metered.

04

Verified Result

Results return to your contract (or HTTPS response) with a hardware attestation report. Anyone can cryptographically verify the exact code that produced the output.

fn main() {

        .unwrap().parse().unwrap();

        .unwrap();

    // Call the AI model

    // Refund unused deposit via SDK
    near::payment::api::refund_usd(
        (deposit - cost) as u64
    );

    print!("{}", json!({ "result": result }));
}
